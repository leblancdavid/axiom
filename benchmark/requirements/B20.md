# B20 — Projects and permission boundaries (architectural)

Projects are JSON objects with `id`, `owner`, and `members`. They have a unique
nonblank case-sensitive ID, an existing owner user ID, and a set of existing
member user IDs including the owner. `create-project
--id ID --owner USER_ID --actor ACTOR` is allowed to that owner or an ADMIN;
duplicates fail `project_exists`; invalid owner fails `invalid_owner`.
`add-project-member --project ID --user
USER_ID --actor ACTOR` is allowed to the project owner or ADMIN and is
idempotent and returns the updated project. `list-projects` returns projects ordered by ID, including members
ordered by ID. Tasks gain optional `project` (empty string means none);
creation may use `--project ID` only for an existing project. Migrated tasks
are unassigned. `list-project --project ID` returns its nonarchived tasks in
normal order. For a project task, a USER may mutate it only if they own the
task **and** are a project member, or if they own the project; ADMIN may
mutate any task. For creation into a project, the actor must be ADMIN, project
owner, or project member and must satisfy B17 ownership rules. Forbidden
operations fail `permission_denied`; unknown project fails `project_not_found`.
