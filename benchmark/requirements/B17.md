# B17 — Roles and actor authorization (architectural)

Users have ADMIN or USER role; `system` is ADMIN. `create-user --role ADMIN|USER`
defaults to USER; user results now include `role`, including the built-in
system user. All mutating task commands require `--actor USER_ID`, an
existing user. A USER may create only tasks they own and mutate only their
own tasks; an ADMIN may create or mutate tasks for any owner. Unknown actor
fails `unknown_actor`, missing actor fails `actor_required`, forbidden action
fails `permission_denied`. Reading/listing remains unrestricted. These checks
precede mutations and must preserve state on failure.
