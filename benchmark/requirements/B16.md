# B16 — Users and required ownership (architectural)

Add users identified by nonblank, case-sensitive IDs. A built-in `system`
user always exists. `create-user --id USER_ID` returns `{"id": USER_ID}`;
duplicate or blank IDs fail `user_exists` or `invalid_user` respectively.
`list-users` returns those objects ordered by ID. Task creation now
requires `--owner USER_ID` naming an existing user; missing or unknown owner
fails `invalid_owner`. Previously unowned tasks migrate to owner `system`;
migration of a task whose nonempty owner ID has no corresponding user fails
`invalid_owner` without changing data. Creating the user and retrying can
resolve it. Existing owner filters continue to work.
