# B19 — Daily recurring tasks (architectural)

Allow creation with `--recurrence-days N`, a positive integer, only when a due
date is provided. Omitted recurrence is null; migrated tasks receive null.
Invalid interval or missing due date fails `invalid_recurrence`. Successfully
completing a recurring task also creates exactly one new pending task with a
fresh ID, same title, description, priority, tags, source, category, owner,
notes and project assignment (when applicable), empty dependencies, a new
creation timestamp, and due date equal to the completed task's due date plus
N UTC calendar days. The successor retains recurrence-days N and is not
created again if completion fails. Completion and successor creation are atomic.
The audit history gains two entries in order: `complete` for the original and
`create` for the successor, both attributed to the completing actor.
