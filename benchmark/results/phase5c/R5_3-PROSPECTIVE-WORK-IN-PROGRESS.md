Parent: `PHASE5C-R5-STATE-RELATIVE/1` (R5.2). The pre-implementation sufficiency proof is `R5_3-ACCEPTANCE-STATE-AUDIT.md`.

`benchmark/harness/acceptance_state_r5_3.py` is an additive pure state-transition prototype. Its proposed rule selects only active assertions whose frozen behavior tags intersect a later amendment's semantic dimensions, moves *all* assertions on the selected method into its specified replacement carrier, preserves earlier supersession edges, and appends carrier IDs to each assertion's chain. It does not read a track name, implementation, prediction, execution or classification. Assertions removed by an earlier amendment are not synthesized. A superseded source remains superseded by its earlier amendment. Different prior histories can select different active sources for the same semantic dimension. A dimension unrelated to an active carrier does not select it. The associated deterministic fixtures exercise the requested A–L scenarios, including the real R5.2 B16/B11 activation metadata.

This prototype is **not yet an executable B17 acceptance composer**. In particular, it still needs a pinned, exhaustive materialization of the *effective* post-B16 R4/R5 suite dispositions into assertion-level prior state; frozen assertion tags and origin/chain mappings for every audited source; pinned replacement source hashes and an executable replacement runner that proves preservation of unaffected assertions. The capability-profile `superseded_cases` alone cannot supply those. No prospective B17 fragment, amendment, oracle, prediction, attempt, classification, checkpoint or freeze has been created. Neither B16 authoritative continuation state is changed. The 29 historical harness tests and eight new fixture methods passed together (37 total); this is not the independent B16 restore-and-suite revalidation required for a protocol freeze.

Do not treat the present files as a frozen protocol revision.
