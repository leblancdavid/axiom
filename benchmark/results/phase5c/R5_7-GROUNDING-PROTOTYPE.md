## Architecture and operation

`benchmark/semantic/grounding_r5_7.py` compiles the fixed, deterministic
`grounding_target_r5_7.py` template into a disposable `operation.py` and a
per-operation `provenance.json` in a temporary isolated directory. The generated
module owns the public entry, `invoke`, durable `read_durable` and `commit`
boundaries. It accepts a typed JSON sequence of `{id: string, label: string,
sealed?: boolean}` vials. The independently seeded `state.json` holds that
sequence. On an unsealed vial the operation defaults `sealed` to `true`, writes
the result, and returns it; if all vials are already sealed, it returns an
`error` classification and the unchanged sequence, without writing. The
implementation is deterministic for the given input and pre-state. The existing
R5.5 contract (`contracts.py`) expresses input = pre, keyed default from pre to
post, and result = post, including the idempotent failure state. It has no
error-envelope or conditional classification semantics; see the **halt** below.

Identity categories are distinct: `seal_vials` is the stable semantic operation
ID in the contract; `unit_0` and `store_0` are compiler-chosen generated
operation/persistence boundary IDs; `generation` is a deterministic compiler
build identity; `artifact_sha256` identifies the generated bytes; the caller's
random per-call `invocation` is a runtime correlation ID. IDs are metadata,
not application concepts. The contract's canonical digest guards changed
meaning behind a stable operation ID. For this single-operation compiler the
fixed boundary names are unique; a multi-operation compiler would have to check
uniqueness and map shared units explicitly.

The manifest includes schema version, operation and both boundary IDs, contract,
binding and template SHA-256, generation ID, variant and artifact SHA-256. The
compiler produces it, not the test. Challenge checks those IDs/digests and
deployed artifact bytes before attaching any verdict. SHA-256 detects drift
under trusted manifest/hash tooling; it is not a signature or proof that the
compiler translated meaning correctly. The generated event carries operation,
invocation, boundary, persistence and generation IDs, classification,
attempted-write flag, and concrete input/pre/outcome/post facts. The target
reads its post-state back from the file, rather than copying the write buffer.
This event is **reported execution**, not self-authenticating evidence.

An independent runner snapshots raw `state.json` bytes and decodes them before
launch, supplies JSON input and its own invocation ID to a subprocess, captures
exit/stdout/stderr without consulting the internal trace, waits for termination,
then independently reopens the file and decodes raw post-state bytes. Public
output is serialized from the live result, not from the trace. The runner
subsequently loads the sidecar trace. Raw SHA-256 and decoded values let the
challenge distinguish endpoint byte changes and mismatched reported state.
For a failure with unchanged endpoints this does **not** establish that no
intermediate write occurred; the attempted-write field is still trusted for
that finer claim. One named file is the entire observed durable scope.

The challenge compares provenance and artifact integrity, entry and invocation,
public input/outcome/classification/exit, internal input/outcome/classification,
boundary IDs, independently read pre/post values and the no-attempt endpoint
claim. On mismatch it reports `provenance_valid=false` or
`grounding_challenge_passed=false`, and leaves `contract_conformant=null`.
Only a consistent event is projected into the **existing** R5.5
`conformance.evaluate`; a separate prototype adapter policy additionally checks
the expected error classification and raw failure no-write endpoints. Verdicts
keep provenance, grounding and conformance separately; even all three true
means only this observed invocation, environment and state view. The R5.5
verifier's own `observed_execution` label alone remains self-asserted; consumers
must use the R5.7 wrapper status, not that label, for grounded claims.

## Fault injection and observed results

`benchmark/harness/test_grounding_r5_7.py` invokes real subprocesses with
independently seeded and readback state. A changed result or stored record is
not mirrored into the expected contract. Fabricated event fields disagree with
an independently captured public argument or file readback.

| Variant | Independent disagreement | Provenance / challenge / conformance |
| --- | --- | --- |
| Baseline success and already-sealed failure | None; committed readback and public result match | valid / passed / true (with adapter failure policy) |
| A wrong result | Public result differs from actual compliant post-state | valid / passed / false |
| B wrong durable state | Raw durable readback contains a changed label while public result is expected | valid / passed / false |
| C false internal post | Actual reopened file differs from reported post | valid / mismatch / not evaluated |
| D false internal input | Caller-supplied argument differs from reported input | valid / mismatch / not evaluated |
| E wrong operation / stale event provenance | Expected operation/generation differs from event | valid / mismatch / not evaluated |
| F modified generated artifact after manifest production | Artifact bytes diverge from manifest | invalid / not passed / not evaluated |
| G error with unintended write | Public error and changed raw bytes; state relation also rejects changed sealed field | valid / passed / false |

The false reports are event-only faults; the runner does not derive external
snapshots from the trace. A and B are implementation failures despite faithful
observation. C/D/E are attribution/observation failures. F is artifact integrity
failure. G is a behavioral failure visible at the independently observed
durable endpoint. This is evidence for case-scoped distinction, not exhaustive
fault detection or correctness for all states.

## Trust, generation and portability

Trusted components still include the semantic contract's intended meaning,
compiler/template and effect-routing completeness, Python execution and JSON
conversion, caller and sidecar correlation, runner/decoder/verifier/hash tooling,
filesystem ordering and an isolated single-writer namespace. Public output and
internal trace share implementation variables and process; the external runner
is a distinct capture path, not an independent second implementation. Caller
chooses the state path; it cannot rule out undeclared sinks or path substitution
by arbitrary target code. No sandbox, locking, atomic replacement, fsync,
intermediate-write tracing, race protection, cryptographic attestation or
all-input proof is claimed. The manifest can be forged if the manifest writer
is compromised; a hash of an incorrect compiler product remains consistent.

Normalization made correlation and fault localization straightforward: stable
machine IDs, deterministic template substitution, per-operation manifest and
explicit read/commit/entry hooks allow reproducible byte-identical regeneration
in two temporary roots. Correctness and traceability were more useful here than
target-code aesthetics; this is not a controlled comparison with idiomatic code
or evidence of lower cost. Python-specific responsibilities are subprocess argv,
JSON serialization, file byte I/O, stdout/error channels and target template.
Abstract contract, four-slot projection, provenance relationships and challenge
statuses do not require Python as a semantic concept. Portability to a second
backend remains untested and would require a separate runner/adapter.

## Construct accounting and semantic halt

Historical numbered inventory is unchanged: core/domain **13**, collection
**11**, state **4**, operation **1** = **29 candidate core**; observation **3**,
verification **2**, evidence/testing **5**, evolution/link **5**,
research/administration **1** = **45 historical raw**. Numbered binding/compiler
**0**, provenance **0**. Newly implemented unnumbered machinery, counted
separately rather than hidden in 45: **binding/compiler 3** (entry map, operation
boundary, persistence boundary); **provenance 2** (build manifest, artifact
integrity check); **observation 3** (internal event, external public capture,
external durable capture); **verification 2** (challenge, adapter error/no-write
policy); **evidence/testing 2** (variant generator, fault matrix runner);
**evolution/link 0**, **research/administration 0**. The expanded inventory
denominator is **57** (45 historical + 12 new non-semantic mechanisms); these
are named implementation responsibilities, not 12 language primitives or a
claim of independent implementation modules.

**Stop before candidate #30:** the exact missing expressive capability is a
typed success/error outcome with conditional transition/no-write obligations
linked to the pre-state and classification. Existing `equals` and
`default_missing` compose a state/result relation and permit an unchanged
already-sealed state, but cannot require an error rather than success on that
state or express a variant-bearing error outcome. That observable distinction
belongs in operation semantics, not provenance, binding or an observer;
transport decoding of errors belongs in binding, and endpoint no-write evidence
in observation/verification. The prototype's adapter policy is explicit
non-semantic scaffolding and **does not repair the contract's expressiveness**.
No #30 was added. As a result the complete failure classification is not
established by semantic conformance alone; this is an important unresolved
boundary, not a reason to silently count the policy as core semantics.

## B01 boundary and next step

This mechanism is architectural evidence relevant to eventual public-call and
durable pre/post-state grounding, but is neither applied to B01 nor sufficient
for its varied interfaces and storage. B01 still lacks actual public-call
grounding, durable pre/post-state grounding, create insertion semantics,
completion framing, migration outcome/version behavior, and resolution of
CRITICAL/“above HIGH” uncertainty. **Recommendation:** first review the
documented conditional error-outcome semantic gap under the 29-construct
ceiling, then prototype a separately checked outcome/binding design only if
authorized; independently challenge intermediate writes and boundary coverage
before any benchmark application. Keep B01 halted and Phase 5C paused.
